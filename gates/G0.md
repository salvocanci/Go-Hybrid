## Evidence highlights (all pre-registered before measurement)

- Safe crossing **2.42 ns** / 0 allocs (budget ≤ 5 ns held); handle get
  0.84 ns; (T, error) ok-path **0 allocs**, error path exactly 1.
- M1 on-stack blocking = **169× starvation** at 1k and **42×+ (capped,
  theory-exact)** at 100k — plus the GC-assist wedge (allocation itself can
  freeze) → two-tier design adopted; M2b (entersyscallblock lane + bounded
  pool) tracks M0 at **1.00–1.19× on every worker cell at 100 000 tasks**;
  P-release proven by a self-calibrating CPU-time canary (syswin/floor =
  1.01). Thread budgets measured environment-specific (sandbox ~717;
  worker 38 508 pids) → derive-by-probe.
- Tier-0 ownership: **0 annotations, 0 managed, 0 outside-model** across
  the ten MVP target programs (strictest reading; hand-trace — machine
  check lands with the Phase-1 checker corpus).

## Two crash findings + one wedge (absorbed, all improved the design)

1. Spike 3: the shared mmap Rust stack is concurrency-unsafe → crossing
   redesigned (caller-stack fast path + pooled guarded deep stacks).
2. Spike 4: uncapped syswin blocking dies at the sandbox's ~717-thread
   wall (Go Ms never shrink) → the bridge owns a hard thread budget via a
   sampler-gated admission controller; blocking pools sized for
   concurrency, not CPUs. (The worker's pids.max = 38508 confirms budgets
   must be derived per environment, never hard-coded.)
3. Spike 4 (worker v8): `gcAssistAlloc` wedged the harness's spawn loop
   for 43 minutes when every P sat in M1's nanosleeps — on-stack blocking
   can freeze allocation itself. M1's third indictment; the two-tier is
   structurally immune.
