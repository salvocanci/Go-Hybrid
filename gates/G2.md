## The gate question

SPEC §3 (performance): "cross-boundary call overhead meets the budget in
section 6, **or the documented fallback from the spikes**." SPEC §6's budget
is the ≤5 ns hypothesis — revised from the original ≤10 ns row after the
spikes, and explicitly flagged there as *a hypothesis*: "The original 'under
5ns' target is a hypothesis. Do not trade safety for it." Spike 1's decision
rule: "Under 10ns achievable and stable under panics/stack growth → keep the
trampoline design."

G1's open item was that the spike numbers (2.82 ns sandbox / 4.36 ns worker,
M4) measured the PROTOTYPE. This gate re-measures the LANDED artifact: the
same hybridge assembly and hyrt staticlib every `hyb build` links, through
the shipping `Cross1` entry point.

## Methodology — `hyb bench-overhead` (Batch J)

`hyb bench-overhead` assembles the bench ON the bridge workspace (the exact
`hyb build` recipe: go.mod module hybrid.program, hybridge + jsonbinding +
overheadbench packages, the cargo-built libhyrt.a), then runs a Go program
that measures a **no-op crossing** — `hybridge.Cross1` → hyrt's `hy_nop`
(one register move, zero payload) — so the measured cost is the boundary
itself. Instrumentation proves WHICH path each number measures:

- `hybridge.DeepPathCount` — a cold-path atomic (the fast path pays
  nothing) incremented on every deep-path engagement.
- `overheadbench.NopRaw` / `hybridge.Cross1Raw` — the fast trampoline
  WITHOUT the Go-wrapper retry (diagnostic only; production uses Cross1).

Two scenarios, because the fast/deep choice depends on goroutine stack
headroom (the in-trampoline guard requires 4096 bytes; the probe found a
fresh main-goroutine stack holds ~2.9 KB):

- **Scenario A — shallow goroutine** (fresh 8 KB main stack): headroom
  < 4096 → the deep path engages on every crossing.
- **Scenario B — grown stack** (200-deep recursion forces contiguous
  doubling): headroom ≫ 4096 → the fast path engages; `DeepPathCount`
  frozen across the loop proves it.

Loop shape = spike 1's (inline, no closure indirection); in-process best of
3 over N=5M; the reported number is the median of 3 separate process runs.
Pins enforced (HYB-E9001): go1.26.9 / rust 1.99.0.

## Verdict

**PASS on the fast path — 3.37 ns ≤ 5 ns (67% of budget)**, with the raw
trampoline (2.65 ns) at parity with the spike's prototype number (2.82 ns):
the design transferred intact. The marginal cost over an equal Go call is
1.25 ns.

**The honest cost of safety, documented:** shallow goroutines (fresh 8 KB
stacks — where most programs START) hold <4 KB headroom and take the pooled
deep path at 19.19 ns until their stacks grow. The delta over the spike's
fixed-single-stack prototype (~16 ns) is precisely the mechanism spike 1's
own probes FORCED: the shared single mmap stack collided under concurrent
crossings (spike 3's TestConcurrentCrossing), so the shipped bridge pays for
the bitmap-pooled guarded stacks (acquire/release per crossing) on the deep
path. This is the "do not trade safety for it" clause operating as written:
the pool stays, its cost is recorded, and the fast path — the steady state
for any goroutine whose stack has grown — meets the budget.

Decision per spike 1's rule: **keep the trampoline design** (fast path on
the caller's stack after an in-trampoline guard; pooled guarded deep path
otherwise). No redirect.
